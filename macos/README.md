# NetScope · Mac 使用指南

适用 Apple Silicon Mac（包括 M4/M5 Mac mini 和 MacBook），最低 macOS 14。主窗口、菜单栏和悬浮窗均为原生 SwiftUI/AppKit。

## 在办公室最快的用法

本轮不依赖 GitHub 安装包发布。先在 Mac 安装 Apple 开发工具（终端运行 `xcode-select --install` 并完成安装），再从你的私有 GitHub 仓库拉取代码：

```bash
git clone https://github.com/Maize9623/netscope.git
cd netscope/macos
bash build.sh
open dist/NetScope.app
```

私有仓库需要你的 GitHub 登录，密码不能直接代替 GitHub 的命令行认证；如果已有 GitHub Desktop，用它克隆也可以。已经拉过代码时，在仓库里执行 `git pull` 后重新运行构建脚本即可。

构建不调用 AI，也不需要把公司网络数据上传 GitHub。安装开发工具是第一次的准备工作，以后通常无需重装。
## 可选的预编译安装包（仅在发布页存在时）

1. 在本私有仓库的 Releases 版本发布页，下载 **NetScope-macOS-arm64.zip**。
2. 解压 `NetScope-macOS-arm64.zip`，得到 `NetScope.app`。
3. 拖到“应用程序”后打开。应用目前使用本地临时签名，未购买开发者证书、未做 Apple 公证。若 macOS 提示无法验证开发者，在确认下载来自自己的私有仓库后，按系统的“隐私与安全性 → 仍要打开”流程操作。不要全局关闭系统安全保护。
4. 第一次打开会自动记录网络，关闭主窗口后菜单栏仍可继续显示。彻底结束请从菜单栏选择“退出 NetScope”。电脑睡眠期间不会有记录，唤醒后的空白不算断网。

没有预编译包时，先安装 Apple Command Line Tools（`xcode-select --install`），在终端进入本目录运行 `bash build.sh`。脚本先跑离线测试，再生成 `dist/NetScope.app` 和压缩包；无需 Homebrew、npm 或 Python。

## 先用“小白模式”

默认页“检查为什么卡”回答六个问题：网络现在怎么了、哪里可能不通、网速是否正常、别的设备是否用网、自己的哪个软件用网、下一步怎么办。

点“立即检查”，软件按电脑连接、常用网站、AI 应用逐项检查。先看中央结论，再逐条展开六项结果；原始记录可以在右上角“详细模式”查看。日间、夜间和跟随系统可随时切换。

**“有回应，尚未测试能否正常使用”不是报错。** OpenAI、DeepSeek 等接口可能要求身份凭证，但已经回应了检查。不需要为了这项基础检测登录每一家；软件没有借此验证聊天生成是否成功。

## 工位卡片怎么用

- **这是什么设备**：按 Wi-Fi/网线、VPN/虚拟连接、来源待确认或导入记录分组。本机多个接口合并为一台 Mac；系统知道的部分附近设备，加上自己导入的路由器记录。能起名字的卡片可以手动命名，名字只保存在本机。
- 卡片说“可能是手机/电脑”时，是依据名称等线索的推测，不是准确识别了型号。苹果设备不自动等于 Mac；未知时保留未知。
- **哪个软件在用网**：点“看看谁正在用网”，读取系统 `nettop` 的两次逐程序字节记录，再按两轮输出到达的实际时间差，计算短时间窗口的近似平均速率；原始字节差也保留，时间无法分辨时不显示速度。可开启每十秒刷新，默认关闭，避免不必要开销。
- 软件名优先用 macOS 提供的应用名称，其次常见名称映射。无法确认归属时保留系统提供的名字，不瞎认成另一个应用。
- 百分比是“这次显示的程序记录中占多少”，不是“占满宽带多少”。VPN 和应用可能记录同一份数据，刚启动或退出的程序也可能漏记。读取失败、格式变更或系统权限不足时显示未知，不自动提权。

## 曲线怎么读

“现在上网怎么样”展示最近十分钟的本机用量；“过去的变化”可选一小时、一天、一周或三十天，查看用量或各应用的回应等待时间。切换网络、暂停、睡眠和缺测会断开曲线，不补成零、不当作失败。

本机流量每两秒读取计数；历史每约三十秒保留一个真实样本，**不是覆盖每一秒的峰值**。导出的用量 CSV 从完整已保存记录读取，不导出屏幕为了绘图缩减过的点。

**当前用量不是宽带最高速度。** Mac 这一版没有主动下载测速功能，不会用当前闲置用量来判断“带宽不够”。Windows 提供单独的小流量手动测试。

## 能不能看到所有设备、谁占网

单台电脑通常只能得到自己通信过或系统缓存中的部分邻居。它不能天然知道全公司每台设备用了多少网。Mac 不比 Windows 拥有绕过交换机、无线隔离或公司网络策略的能力。

要观察其他设备用量，需要路由器/网关提供记录。可以导入 CSV：

```csv
ip,mac,name,device_type,download_bps,upload_bps,observed_at
```

速率单位是 bytes/second。`observed_at` 应包含时区，例如 `2026-10-29T15:00:00Z`。空速率保留未知；导入是历史快照，不冒充实时数据。不能仅凭设备在线就说它“抢网”。

Windows 新版另外提供用户主动触发的有限 IPv4 设备查找、名称查询和匿名 AI 类型推测；Mac 本版保留被动缓存、系统/网关名称、规则类型推测与手动命名，尚未提供这三个额外按钮。

## AI 如何工作，怎么控制开销

先在这台 Mac 上安装并登录 Codex。软件尝试寻找 Codex.app 自带的命令行程序以及 `/opt/homebrew/bin/codex`、`/usr/local/bin/codex`。找不到时，在“我的设置”填写实际可执行程序位置。

AI 通常每三十分钟分析一次，新问题最多每五分钟提前触发一次，默认每天最多六十次。可在“额度与开关”关闭自动 AI，或降低频率/次数。关闭 AI 后基础记录和本地判断继续。

每次发送经过筛选的匿名摘要，包括公开目标类别、时间、测得数字，以及可用时匿名的逐程序用量。不会发送本机 IP、MAC、设备人名、自定义网址、完整程序列表、网络内容或登录密钥。AI 只能根据这些记录分析；无法确认时应说“目前还判断不出来”。详情里保留那一次实际发送的输入，避免拿新数据解释旧报告。

额度通过 Codex 的只读账号接口查询。百分比/恢复时间/积分/重置次数/到期时间若账号没有提供，就显示未知。不会使用重置机会。实际分析调用会计入账号用量；失败也可能耗费额度，缺少 token 回执时保留未知。

## 监测方法和准确性

| 项目 | 获取方式 | 不能据此断言 |
|---|---|---|
| 本机流量 | 系统接口的 64 位累计计数，按真实时间差求速率 | 不是宽带容量，也不是全网流量 |
| VPN/虚拟连接 | macOS 接口名称和类型线索 | VPN 显示连接不等于节点健康 |
| 网站检查 | 独立 URLSession 的 HEAD 请求，不跟随跳转，最多四个并行 | 收到回应不等于登录或生成内容正常 |
| 等待阶段 | URLSession 实际事务时间（解析、连接、安全握手等） | 缺失阶段不补零；复用或代理时可能不可得 |
| 访问方式 | 系统配置 + URLSession 的实际代理标记 | 不能自动看穿公司中转或透明 VPN |
| 设备信息 | 被动读取 arp/ndp 缓存 + 用户导入/命名 | 不扫描整个网段，列表不保证完整 |
| 逐程序流量 | 用户主动启用的 nettop 记录 | 不表示异常软件，也不一定覆盖全部程序 |
| 本地提醒 | 多目标对照、重复检查、同一路径历史基线 | 单次异常不等于确定责任方 |

软件不关闭 VPN、不修改 DNS、不限制其他设备，不读取通信正文。macOS 的安全连接策略仍按系统默认执行；普通 HTTP 地址被系统拒绝时，记录为检测配置限制，不说成网络断了。

## 数据放在哪里

`~/Library/Application Support/NetScope/`。设置、原始按日 JSONL、设备标签、最近 AI 报告和本应用调用用量都留在这里。默认保留三十天，可改为一至九十天。不会把这些文件上传代码仓库。
