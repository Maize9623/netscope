# NetScope 网络助手

打开后记录网络变化，卡顿时回答：**现在怎么了、哪里可能不通、谁在用网、下一步怎么办。**

本仓库分别保存 Windows 和 Apple Silicon Mac 的代码。原始记录保存在使用者自己的电脑上，不随代码上传 GitHub。

## 从哪里开始

- **Windows**：使用打包好的 NetScope.exe。完整教学见 [Windows 使用指南](windows/README.md)。
- **M4 / M5 Mac mini、MacBook**：使用构建产物 NetScope.app。安装和功能差异见 [Mac 使用指南](macos/README.md)。
- 本轮以源码交付为主：Mac 拉取仓库后运行 `bash macos/build.sh`，即可得到 `macos/dist/NetScope.app`。Actions 只做自动验证，不占用安装包存储。
- 开发者：Windows 运行 `windows/build.ps1`；Mac 运行 `bash macos/build.sh`。

## 默认先看六件事

1. 现在上网顺不顺？
2. 哪一段可能不通？
3. 网速是否正常？
4. 其他设备谁在用网、谁用得多？
5. 我的电脑里哪个程序用得多？
6. 我应该怎么做？

“小白模式”先展示结论；“详细模式”展开完整数字、时间、地址、检测过程及判断依据。没有测到的数据明确显示不知道，不用猜测补齐。

## 数据能说明什么

- 电脑当前下载/上传量，是正在使用的流量；不是宽带最大速度。
- 网站有回应，说明该次检查收到了回应；不等于账号已登录、聊天生成正常。
- 单次超时只说明这一次没等到回应；不能断言 VPN 或某家公司出了故障。
- 同一条网络的多次记录可以帮助缩小排查范围；最终定位有时需要手机热点、路由器数据或 IT 协助。
- 设备列表来自本机系统缓存和手动提供的路由器记录，不保证看到全网全部设备。仅凭 IP/MAC 不一定能确认设备型号或主人。
- 其他设备用了多少网通常需要路由器提供数据；软件不会把“有几个连接”伪装成流量。
- Windows 的逐程序字节统计需要用户主动开启增强检测；Mac 的支持情况以平台指南和验证记录为准。

## AI 与额度

使用本机已经安装并登录的 Codex CLI。默认发送缩短后的匿名测量摘要，完整原始记录留在本机。自动分析可关闭，关闭后网络采样和本地判断继续。

AI 通常每 30 分钟分析一次，异常触发有冷却，每天设调用上限。调用会消耗真实账号额度，具体 token 以返回的 usage 为准，未返回则显示未知。额度页只读查询账号共享额度、恢复时间、重置机会及到期时间；没有查询到就显示未知，不推测余额。

## 挂机开销

默认每 2 秒读取本机计数、每 30 秒检查 7 个公开目标。常规检查使用 HEAD，不下载网页正文；手动测速会短时占用网络。AI 有额外联网及额度开销。本项目没有承诺固定的每日流量，也尚未完成全天负载测试。

## 目录

| 目录 | 内容 |
|---|---|
| `windows/` | C# / .NET Framework Windows 程序、依赖许可、离线测试、教学文档 |
| `macos/` | SwiftUI / Swift Charts / AppKit 原生 Mac 程序、离线测试与打包脚本 |
| `shared/` | 两个平台共用的测量含义与测试案例 |
| `docs/` | 版本、验证范围与已知限制 |

## 验证与边界

以 [验证记录](docs/validation.md) 和 GitHub Actions 实际结果为准。编译成功、离线测试通过，不等于已在每台 M4/M5 真机和公司网络上完成长期验证。

软件只观察与建议，不会限制他人网速、修改 DNS、关闭 VPN 或自动调整系统网络。
