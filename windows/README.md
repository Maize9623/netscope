# NetScope 网络观测站

**Windows 第一版 · 先看结论，需要时再展开证据。**

它帮你记录“什么时候慢、哪些路径一起慢、电脑上的哪些进程在传输”，再把证据交给已登录的 Codex 做分析。它不自动修改网络、不限速、不把猜测当事实。

## 1. 第一次打开：先做这五步

1. **双击 `NetScope.exe`。** 请保留旁边的 `lib` 文件夹和 `NetScope.exe.config`，不要只复制一个 exe。普通监测不需要管理员权限；系统要求是 Windows 10/11 x64 与 .NET Framework 4.8。
2. **看“实时总览”。** 启动后先建立计数基线，出现“等待采样”很正常；几秒后显示本机收发速率。第一轮网络探测完成后，会显示各目标的真实结果。
3. **点“自定义”，选你关心的目标。** 已预置国内网站、国际网站、开发服务和多家 AI API。可以关闭不关心的项目，添加公司内网或自己的测试 URL。建议始终保留至少一个国内/内网对照和两个不同的外部对照。
4. **看“AI 分析”。** 内部分为“结论 / 完整依据 / 额度”。不想消耗模型额度时，点“暂停自动 AI”，本地采集、曲线和规则记录继续运行。
5. **先运行 10–30 分钟。** 刚启动只有一两个样本，程序还不知道你的网络平时是什么水平，很多判断会显示证据不足。

最小化后可以从托盘和悬浮窗查看；关闭主窗口会继续留在托盘。真正退出请用托盘菜单。睡眠、关机、退出期间不能采样；空白时段不等于断网。

## 2. 只记住两个概念，就能开始看

### “现在用了多少”与“还能跑多快”不同

- 首页下行/上行是**当前使用量**。后台没下载，显示很低是正常的。
- 网卡的“1000 Mbps”等数字是**协商速率**，不是你的实时网速，也不是公司的互联网带宽。
- 手动测速是对一个指定目标的一次小下载，反映当时这条路径的表现，不能证明线路最高速度。

界面流量用 B/s、KiB/s、MiB/s；测速用 Mbps。B 是字节，bit 是位：1 MiB/s 约等于 8.39 Mbps。

### “等了多久”与“传了多少”不同

- **延迟/响应时间**用 ms 表示，越小通常等得越短。
- **吞吐速率**用每秒字节或 Mbps 表示，反映一段时间传了多少。
- 可能出现“网页打开慢，但打开后下载很快”，也可能“很快连上，但下载很慢”。不要用一个指标代替另一个。

## 3. 程序实际怎样监测

| 项目 | 采集方式与默认节奏 | 正确读法 |
|---|---|---|
| 本机流量 | 每约 2 秒读取 Windows 网卡累计收发字节，计算差值 | 只计算选中的一个接口，物理接口和虚拟接口不相加 |
| 长期流量曲线 | 将约 30 秒内的有效样本按时间加权平均，另保存桶内采样峰值与样本数 | 图上的线是平均值；短尖峰可从峰值字段复查，不是每个数据包的最大瞬时速率 |
| 网卡/代理 | 读取接口状态、地址、网关、DNS、系统代理摘要 | 虚拟网卡是启发式识别；存在虚拟接口不等于 VPN 出口健康 |
| 网关 | 每轮一次有限超时的 ICMP Ping | 不回应可能是禁 ICMP；不能仅凭它判断断网 |
| 本机 DNS | 调用本机解析器，可能命中缓存 | 不是向权威 DNS 服务器做独立测速 |
| 直接 TCP | 对解析得到的首个 IP 建连 | 仍可能通过 VPN/TUN；不一定与 HTTP 系统代理走同一条路 |
| HTTP | 默认约每 30 秒发轻量 HEAD，最多 4 个并发，默认超时 8 秒；不跟随重定向 | 测到的是收到响应头的总耗时，包含相关连接、代理、TLS 开销；当前探测使用 TLS 1.2 |
| 手动下载测速 | 指定单个公共测速目标，最多 10,000,000 字节或 20 秒 | 只代表该目标、该时刻、该路径；不会后台反复跑大流量测速 |
| 本机连接 | 读取 Windows TCP 连接表，关联进程 PID | 包括 IPv4/IPv6 连接；连接数量不是带宽占比 |
| 局域网设备 | 读取本机已有邻居/ARP 缓存；可导入网关快照 | 不扫描整个网段；看不到的设备不能说不存在 |
| 账户额度 | Codex app-server 的只读账户接口，默认约 10 分钟刷新 | 查询不会调用模型，也不会使用你的重置机会 |

探测没结束时不会叠加启动下一轮，因此“30 秒”是目标周期，不保证每个目标严格在同一毫秒采样。每条数据保留实际时间。内部繁忙或环境错误导致未执行测量，会标为漏测/采集异常，不算服务断网。

网络配置指纹用于区分网卡、网关、DNS、代理等配置变化。它**不能识别 VPN 软件内部悄悄切换的真实远端节点**。如果某个应用另设了自己的代理，它可能和本程序不同路。

## 4. HTTP 状态：不要把红色数字都当断网

| 结果 | 大白话 | 不应直接得出的结论 |
|---|---|---|
| 2xx | 这个地址给了成功响应 | 不能证明 AI 推理、账号、长连接都正常 |
| 3xx | 这个地址让请求跳转，程序没有跟着跳 | 不能说最终目标已验证 |
| 401 | 对方要求身份验证 | 不是断网；本程序没有拿你的密钥调用该家模型 |
| 403 | 请求被拒绝，原因可能是权限、地区或策略 | 不能只凭这个说公司网络断了或服务商宕机 |
| 404 / 405 | 地址或 HEAD 方法不适用，但收到了回应 | 不等于网络传输失败 |
| 407 | 代理要求认证，尚未验证目标服务 | 不能拿代理自身的回应证明目标服务正常 |
| 429 | 收到了限流响应 | 不一定是你的账户额度耗尽，也可能来自中间层 |
| 5xx | 服务、CDN 或中间代理给了错误响应 | 单机无法直接确定是哪一层负责 |
| 超时/连接失败 | 本轮没有在时限内收到响应 | 可能是路径、拦截、节点、目标或短时波动，需要对照 |
| 漏测/采集异常 | 检测器没有完成有效测量 | 不是目标故障；不放进网络失败率分母 |

“HTTP 可达率”把所有收到 HTTP 响应的样本算作可达，包括 401/403，也会记录代理自身的 407。407 不作为目标已成功访问的正对照。它不是 AI 可用率，也不是丢包率。状态页地址的 HTTP 200 只证明状态页能访问，本版没有把它解释成厂商所有系统都正常。

## 5. 本机精细分析：哪些进程在用网络

普通模式先看连接表。要看进程收发字节，在“设备与连接”启用**本机深度监测**，由你在 Windows 弹出的 UAC 中确认管理员权限。取消授权也能继续用普通模式。

深度模式使用 Windows ETW 的 TCP/UDP IPv4/IPv6 收发事件：

- 记录 PID、程序名、进程启动标识、事件字节、采样窗口、累计量与采集完整性。
- 不读取通信内容，不保存网页、文件内容、命令行，也不安装抓包驱动。
- 每约 2 秒提供当前窗口；你可以选中进程查看当前运行最近 10 分钟的曲线，导出长期记录为 CSV。
- 父程序退出或点击停止后，辅助采集器停止自己创建的会话。

**最容易误解的地方：**应用发出的数据经过 VPN/代理后，可能又以代理进程的名义出现一次。因此“观测事件占比”是在所观察事件中的比例，不能称为物理网卡带宽占比，也不能把所有进程事件相加当作宽带总量。事件缓冲、重传和丢事件也会影响统计，界面会保留限定和完整性标记。

进程规则首先和自身历史比较：最近 10 分钟至少 10 个有效样本，连续两次超过中位数 5 倍且高于 256 KiB/s，才提示明显增长。持续上传另记为活动提示，**不是恶意软件判定**。更新、云同步、会议都可能合法地产生大流量。

## 6. 其他设备：名称能认，带宽要有来源

设备页的名称可能来自：本机 Windows 自报、你导入的网关记录、或你亲自填写的标签。未知就显示未知，不让 AI 凭 MAC 猜“这一定是某人的 Mac”。

你可以选中一个有有效 MAC 的设备，点“命名选中设备”，写成“我的 MacBook”或“会议室电视”。这只是本地记事，不改设备配置、不绑定路由器。给多个已确认地址填同一名称，可以记住同一设备的不同接口；清空名称可取消标签。

苹果私有 Wi-Fi 地址可能按网络不同或定期变化，MAC 并非永久身份。AirDrop 使用蓝牙发现和点对点 Wi-Fi，不代表你能从普通公司网络中把其显示名准确对应到某个 MAC。Bonjour/mDNS 自动发现尚未实现。

邻居缓存的“采集时间”是读取缓存的时间，**不是设备最后在线时间**；“Stale”等是缓存状态。公司 VLAN、无线隔离也会限制你的可见范围。

想知道别的设备占多少带宽，需要它所在网关/AP/路由器提供真实遥测。当前支持导入 CSV 快照，模板是 `gateway-devices-template.csv`：

```
ip,mac,name,device_type,download_bps,upload_bps,observed_at
```

速率列是字节/秒。时间使用带时区的 ISO 8601，如 `2026-10-29T20:00:00+08:00`。无有效时区的时间显示未知。导入是**快照，不是实时连接网关**。本版尚未接入你公司网关，所以不能宣称已经知道全公司的实时流量排名。

## 7. AI 怎样判断，怎样控制消耗

默认复用本机已登录的 Codex CLI，不抄取认证凭据，不需要再填 API key。自动模式每约 30 分钟做趋势复盘，新异常可触发分析，自动触发之间至少间隔 5 分钟；手动体检也可能触发。默认每日上限 60 次，都能在自定义里调整。

报告默认只展示：一句大白话结论、优先排查方向、把握程度、关键数字和不同解释的排序。点完整依据可看输入摘要、详细分析与导出。备选解释会注明有依据/可能/不支持/未知，不把模型自报的百分比当科学概率。

发给模型的是有长度限制的统计摘要，不是所有原始数据。未知程序名、自定义监测地址使用代号；不发送 IP、MAC、公司域名、完整进程列表、命令行或通信内容。常见公开软件名称可保留。报告会标出证据不足或摘要截断；原始数据完整保存在本机供复查。

**用量要看实测：**一轮已验证的纯文本分析返回 15,932 输入 token、456 输出 token，包含 Codex 调用自身的上下文；结构化报告可能不同。不能只用摘要字数估计消耗。界面将本应用的调用/token统计与整个账号共享额度分开。

在“额度”标签可以看接口返回的剩余额度、恢复时间、积分原值、重置机会和到期时间。未返回的值显示未知，不填成零；积分不擅自换算成钱。额度查询是只读的，程序没有自动兑换重置机会的功能。

**不想用 AI 时：**点“暂停自动 AI”，保留全部原始监测和规则分析。显式点击“立即分析”仍是一次主动调用。

## 8. 带去公司挂机一天：按这个流程做

### 开始前

1. 解压整个文件夹，启动程序。
2. 在自定义加入一个你经常访问的公司内网地址；同时保留国内和多个外部目标。
3. 到网卡页核对实际工作的 Wi-Fi/以太网与疑似虚拟网卡。流量卡只能选一个承载接口，避免重复计数。
4. 保留默认 30 秒探测先运行；若需要更密的采样，可调整到允许的更短间隔，但频繁请求也可能引起限流。
5. 根据公司规则决定是否启用管理员深度模式，设置 AI 开关和每日上限，再最小化。

### 卡顿发生时

记下大概时间和哪个应用卡。点一次手动体检；若怀疑吞吐量，另点一次下载测速。不要马上连改 DNS、换节点和重启，否则多个条件一起改变，很难知道哪个动作有效。

### 一天结束后

先选历史曲线的 24 小时范围，找到卡顿时间。比较同一时段的网关、国内/内网对照与多个外部目标，再看事件记录。如果开了深度模式，再查对应进程记录。导出该时段 CSV 和中文报告。

| 同一时段看到的现象 | 优先验证的方向 | 仍需要什么证据 |
|---|---|---|
| 内外网都慢，且网关也反复升高 | 本机、Wi-Fi/网线、本地接入 | 换有线或另一台设备对照；ICMP可能被降优先级 |
| 国内/内网稳定，多个外部目标一起慢 | 共同出口、代理、节点、分流路径 | 用独立网络测同目标，或查看网关出口数据 |
| 只有一家服务或一个地址异常 | 该目标的路径、策略、CDN或服务 | 同时间第二网络与官方状态、实际应用错误 |
| 本机某进程流量增加，与卡顿重合 | 更新、同步、下载等本机活动 | 看程序当时任务及物理接口，不能仅凭相关性认定因果 |
| HEAD正常，实际AI应用仍卡 | 认证、应用代理、流式连接或推理环节 | 应用自己的错误日志/请求耗时；本版没有替你对所有模型做付费推理测试 |

向 IT 反馈可以只说：

> 在某个时间段，内网对照有响应，但多个外部目标同时变慢；附件保留了各目标时间、响应码、延迟、代理路径和原始记录。请对照该时段出口及分流日志。

比“肯定是节点垃圾”更有用，也给对方留下可核对的证据。如果另一台设备或另一条网络结果不同，继续记录这个差异。

## 9. 数据放在哪里，怎样复核

默认目录：`%LOCALAPPDATA%\NetScope`。可用 `NetScope.exe --data <目录>` 自定义。

- `settings.json`：你的目标和开关。
- `history-日期.jsonl`：流量桶与原始探测字段，包括时间、目标、URL、状态、路线和网络配置指纹。
- `events-日期.jsonl`：规则发现、证据与建议。
- `process-日期.jsonl`：启用深度模式后实际读到的进程样本及累计/完整性信息。
- `ai-日期.jsonl`、`last-ai.json`：发送的匿名摘要与模型结果。
- `ai-usage.json`：本程序记录的当天调用与返回用量。
- `device-labels.json`：人工设备标签。

默认保留 30 天，可改 1–90 天；普通监测、进程记录和分析日志按日清理。深度模式记录较多，可按需要缩短保留期。重启恢复已保存历史；进程弹窗的 10 分钟内存曲线从当前运行开始，长期原始记录仍可导出。

原始本地报告可能包含网络地址和设备名；匿名 AI 摘要与原始导出是两份不同用途的数据。给别人发送原始报告前，请自己检查内容。

## 10. 验证范围与已知边界

这是可运行、可复核的第一版，不是经过所有公司网络认证的商业监控系统。已进行本机真实端点/代理路径测试、已登录 Codex 分析与额度查询，以及多组离线回归；详情见 `验证记录.md`。

尚未完成：你公司网络的整天现场验证、管理员 ETW 在你授权后的真实事件对照、各品牌网关的自动实时接入、全网设备OS准确识别、macOS版本、所有AI服务的登录/推理/流式会话健康检查。

程序的价值是缩小范围、保存证据；单台机器和一个模型都不能保证对所有故障唯一归因。

## 小白模式：先回答你关心的六个问题

打开后默认进入“检查为什么卡”。点击“检查现在为什么卡”，会查看电脑连接、常用网站和 AI 服务，并给出六张结果卡：现在网络怎么了、哪里可能连不上、网速是否需要再测、别的设备是否占网、本机哪个程序在用网，以及下一步可以做什么。

“现在还查不到”会同时说明原因和继续检查的方法。电脑当前下载量不是宽带最高速度；一次服务回应也不代表账号或 AI 生成功能已经验证。别的设备用量需要路由器提供记录；本机程序用量需要你点击按钮并同意 Windows 管理员提示才会开始统计。

“这是什么设备”以卡片展示设备和程序，名称未知时不会乱猜。可给有效 MAC 对应的设备起名字并写备注；类型提示与人工确认分开显示。日间/夜间主题和详细模式会保存在本地，下次打开保持选择。右上角“详细模式”可以展开地址、原始测量和完整表格；默认模式保留结论与操作入口。关闭主窗口会继续在托盘后台运行，托盘菜单的“退出”才会彻底结束。
## v0.2：看不懂技术词时，从这里开始

打开后默认是“小白模式”。“检查为什么卡”用六张卡回答：现在网络怎么了、哪里可能不通、网速是否正常、别的设备是否占网、自己的哪个软件用网、应该做什么。完整地址、响应码、原始记录在“详细模式”展开。日间/夜间和模式选择会记住。

“有回应，尚未测试能否正常使用”表示网站已经回答了检查；OpenAI / DeepSeek 的身份验证提示不代表断网，也不要求你为了基础检查登录它们。实际聊天能否成功是另一项验证。

设备页是工位卡片，同一 MAC 的多个地址合并，本机多个接口合并为“这台电脑”。广播/组播等并非单台设备的记录只在详细表保留。本机卡片可用的流量直接来自当前选中的本机连接；其他设备没有网关数据时仍明确未知。

- “尝试认出名字”：只向系统查询当前已经知道的至多 32 条邻居记录，不扫描整个网络、不探测设备端口。底层最多两项名称查询，每项等待最多两秒；忙时不无限堆积，查不到不编造名字。网络提供的名字仍不证明主人身份。
- “AI 帮我认认”：先提取公开名称中的白名单类别线索，例如 iPhone、MacBook、Android、打印机；不会发送原始设备名、IP、MAC 或人名。没有线索的设备不发给 AI 硬猜。推测显示“可能”，不会覆盖你确认的名字或本机身份。调用计入与普通分析相同的每天上限，消耗真实 Codex 额度。
- “给它起名字”：本地绑定可识别的 MAC。设备更换/随机化 MAC 后可能需要重新确认；同名设备不会自动合并。
- 本机程序优先显示微信、Chrome、Cursor 等常见软件名或系统文件描述。无法确认时保留原名。代码名在详情中仍可查。

AI 报告先说大白话结论、为什么这样说、下一步操作。技术词和完整记录留在详情。旧报告有自己的生成时间；新检查不会偷偷替换旧报告当时所看到的输入。
