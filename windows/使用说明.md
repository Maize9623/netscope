# NetScope 网络观测站 · Windows 预览版

双击 `NetScope.exe` 启动，不需要管理员权限，也不需要安装 Python 或 Node。Windows 10/11 需要 .NET Framework 4.8。

## 先看哪里

- **实时用网**：本机当前收发流量、各目标响应、近期曲线。
- **网络检查**：比较网卡、网关、DNS、直接 TCP 和使用系统代理的 HTTP 响应；下载测速单独手动触发。
- **历史曲线**：选择时间范围与服务，查看真实采样；缺测时段不当作零。
- **网卡与路由**：物理接口、疑似虚拟接口、IP、网关、DNS、系统代理摘要。自动选择的流量接口可以改。
- **设备与程序**：本机邻居缓存和进程 TCP 连接；可导入路由器/网关导出的设备带宽快照。
- **异常记录**：时间、证据、判断置信度与下一步验证。
- **AI 帮我看**：查看发给 Codex 的脱敏摘要、最近分析与实际用量。
- **设置**：勾选/添加/编辑服务、公司内网与节点测试地址，调整周期、通知、网卡、保留天数和 AI 策略。

最小化后继续监测并显示悬浮窗；双击悬浮窗或托盘图标恢复。关闭主窗口会进入托盘，真正退出请用托盘菜单的“退出”。电脑休眠、断电、退出程序期间不采样。

## AI 如何接入

使用本机已经登录的 Codex CLI；不复制或保存账号凭据，不需要再填写 API key。默认每 30 分钟复盘，出现新的异常时可触发分析（自动异常触发至少间隔 5 分钟），手动体检后也可触发。默认每日上限 60 次，可调整或关闭。

分析会消耗当前 Codex 账号的共享额度。界面显示 CLI 返回的输入/输出 token；没有返回时不能视作零成本。一次 CLI 调用还可能包含系统提示等额外 token，因此不能仅按摘要字数估算费用。定时 AI 只在 NetScope 运行时工作。

匿名摘要包含测量时间、预设公共目标名或“自定义目标”代号、延迟、响应码、接口数量和统计；不包含 IP、MAC、自定义域名、完整进程列表、网页内容、通信内容或密码。可在 AI 页面预览。输出保存在本机。模型只给建议，程序不自动改 DNS、代理、防火墙或限速。

## 指标准确含义

| 指标 | 含义 | 不能说明什么 |
|---|---|---|
| 本机下行/上行 B/s | 选中网卡累计字节计数的时间差分 | 不是线路可用带宽，也不是所有设备合计 |
| 网卡 Mbps | 操作系统报告的协商速率 | 不是当前网速或宽带套餐速度 |
| 本机 DNS ms | 当前电脑的解析耗时，可命中缓存 | 不能单独证明 DNS 服务器健康或劣化 |
| 直接 TCP ms | 首个解析 IP 的直接连接测试，仍可能经过 VPN/TUN | 不一定与系统代理 HTTP 走同一路线 |
| HTTP 响应头 ms | 当前配置下收到 HTTP 响应头的总时间，包含相关连接/代理/TLS开销 | 不是纯服务器处理耗时，也没验证模型推理 |
| HTTP 可达率 | 采样中收到任意 HTTP 响应的比例 | 不是模型可用率，不是丢包率 |
| 手动下载测速 Mbps | 对单一测试地址、当前路径的有限下载估计 | 不是 ISP 带宽上限，不能拆分节点与服务端瓶颈 |

401/403/404/405 代表收到 HTTP 响应，可能需要认证、被拒绝、路径不适用或方法不支持。429 是限流响应；5xx 可能来自服务、CDN 或代理。状态页目标的 HTTP 200 只证明状态页可访问；本版不把页面可访问当作厂商状态为正常。

“国内/国际/AI”等分组由用户配置，是对照类别，不是验证过的地理路由。虚拟网卡识别是启发式；有些虚拟接口并非 VPN，部分 VPN 只使用系统代理。

## 为什么不能直接看到全公司的设备网速

普通电脑在交换网络中通常只能看到自己的流量和邻居缓存，不能从 ARP 表推导其他设备的实时带宽、操作系统或全部在线设备。未知内容显示未知。本版不会抓取其他人的通信内容、扫描网段或控制其他设备。

设备带宽导入使用 `gateway-devices-template.csv` 的列：
`ip,mac,name,device_type,download_bps,upload_bps,observed_at`

`download_bps` / `upload_bps` 单位为 **字节/秒**；`observed_at` 使用带时区的 ISO 8601，例如 `2026-10-29T20:00:00+08:00`。导入是历史快照，不是持续同步。只有获得网关/AP/路由器提供的实际流量遥测，才能进一步做全网络实时占用排名；不同品牌需要各自接入，尚未冒充实现。

## 数据、导出与维护

默认数据目录：`%LOCALAPPDATA%\NetScope`。历史和事件按天保存 JSONL，默认保留 30 天，可改为 1–90 天；重启恢复历史。设置保存在 settings.json；AI分析和用量另外保存。原始测量 CSV 与中文报告可从界面导出，方便给 IT 对照时间检查。

本地报告含网络地址；匿名 AI 摘要不含网络地址。导出原始报告给别人之前请自行检查其中的公司网络信息。

可以用 `NetScope.exe --data <目录>` 指定数据目录。源码和 `build.ps1` 随包附带，便于复查测量与诊断逻辑。本版是可测试的第一版，并未完成整天挂机、多种公司网关和 macOS 的现场验证。

## 结论怎样才有说服力

先保留某次异常前后同一时间的多目标记录，再用第二条独立网络对照；必要时加上公司网关的出口延迟、会话/带宽、丢包与设备流量。单机只能缩小范围，不能凭单个响应时间证明“IT说错了”或“AI供应商出故障”。模型输出也可能出错，应以它引用的原始记录为准。

实现参考：Microsoft NetworkInterface / IPInterfaceStatistics 计数器；Windows IP Helper 连接与邻居表；[Codex 官方非交互模式说明](https://learn.chatgpt.com/docs/non-interactive-mode)。

## 本机深度监测（可选）

在“设备与程序”点击启用，Windows 会要求你确认管理员权限。该模式使用系统 ETW 网络事件，统计 TCP/UDP 收发事件的字节，不抓取网页、文件或通信载荷，不安装网络驱动。拒绝管理员授权后，普通监测仍正常工作。

每行显示进程、事件收发字节、观察窗口内速率、观测事件占比。**应用和 VPN/代理可能在不同层被重复观察，因此该占比不是物理网卡带宽占比。** 丢事件、样本过期和采集失败会单独标出，不填成零。ETW 会在停止模式或退出主程序时停止。深度模式采样记录也按保留天数清理。

## 额度与简明报告

“AI 帮我看”分成结论、完整依据、额度三层。首页只给结论和关键数字；原因排序使用有依据/可能/不支持/未知及高/中/低把握度，不展示模型虚构的精确概率。原始数据不因界面精简而删减。

额度通过 Codex 本机 app-server 的只读账户接口查询，包含接口实际提供的窗口剩余比例、恢复时间、积分原值、重置机会及到期时间。缺失值显示接口未提供。积分原值不换算成美元或 token。额度查询不触发模型调用、不使用重置机会；默认每 10 分钟刷新。

实测一轮旧版纯文本 Codex 分析返回 15,932 输入 token 和 456 输出 token（包含调用上下文）；新版结构化报告消耗可能不同。请以应用显示的实际回传用量和共享额度为准。自动分析默认每 30 分钟且有每日上限；“暂停自动 AI”保留数据采集。隐私摘要会用代号替代未知程序名，仅对预设常见软件保留公开程序名称；不发送完整进程列表、命令行、IP、MAC或自定义域名。

## 设备名称

“命名选中设备”将 MAC 与你的本地标签关联，支持同名标签对应多个你已确认的地址；清空名称可移除标签。它不修改设备或网络配置，也不是身份认证。私有/轮换MAC会变化，旧标签不会自动证明新地址是同一设备。本机 Windows 名称来自系统自报；网关导入名称注明来源；未知设备保持未知。本版尚未主动实现 Bonjour/mDNS 自动发现。
